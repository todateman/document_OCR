# 検査成績書 OCR 良否判定

検査成績書の画像から計測値を OCR で読み取り、規格に対する良否を判定するツールです。

検査成績書は社外秘のため、クラウドの AI サービスは使わず、**すべてこの PC 上で処理**します。画像が外部に送信されることはありません。

## できること

- 書類の様式ごとに**設定ファイル（様式）を切り替えて**読み取る
- 画像（スキャン）のほか、**PDF（電子・スキャン）と Excel** の検査成績書も読める。電子 PDF と Excel は、OCR を使わずに文字をそのまま読むので読み誤りが起きない（[PDF・Excel の読み取り](#pdfexcel-の読み取り)）
- 様式の作成・編集から判定の実行まで、**GUI だけで操作**できる（プログラムの知識は不要）
- 読み取った値が規格内か判定する（OK / NG）
- OCR の読み誤りの疑いがある値を「要確認」として知らせる
- 総合判定（合格 / 不合格 / 要目視確認）を表示する（コマンドラインでは終了コードでも返す）

様式は 2 種類あります。

| 種類 | 対象 | 読み取り位置の決め方 |
| --- | --- | --- |
| 汎用様式 | どんな書類でも（例: `sample/denshitenbin_kensa_seisekisho01.jpg` の電子天秤検査成績書） | GUI で基準画像の上に枠を描いて指定。読み取る画像は基準画像に自動で位置合わせする |
| NeoMag 専用 | `sample/inspection_sample.gif` と同じ様式 | 罫線から自動検出。最大値・最小値・平均値の再計算照合など専用のチェックあり |

同梱の様式（`configs/` フォルダ）:

| ファイル | 様式 |
| --- | --- |
| `configs/neomag.yaml` | NeoMag 検査成績書（NeoMag 専用） |
| `configs/denshitenbin.yaml` | 電子天秤検査成績書（汎用様式。基準画像は `configs/denshitenbin.jpg`） |

## 実行ファイルで使う

Python の環境構築なしで使えます。[Releases](https://github.com/todateman/document_OCR/releases) から環境に合うファイルを取得してください。

| ファイル | 動作対象 |
| --- | --- |
| `*-windows-x64.zip` | Windows 10/11（x64） |
| `*-macos-arm64.tar.gz` | macOS 14 以降（Apple Silicon） |
| `*-linux-x64.tar.gz` | Ubuntu 22.04 以降（x64） |
| `*-linux-arm64.tar.gz` | Ubuntu 22.04 以降（arm64）、Raspberry Pi OS 64bit Bookworm 以降 |

Raspberry Pi OS 32bit、Raspberry Pi OS Bullseye 以前、Intel Mac には対応していません（`onnxruntime` の配布がない、または glibc が古いため）。

1. **自分が書き込めるフォルダ**に展開します（Program Files や `/opt` に置くと設定を保存できません）。
2. フォルダ内の `document_OCR`（Windows は `document_OCR.exe`）を起動します。コマンドラインで使うときは `document_OCR_cli` です。
3. 試すときは、判定タブで様式「電子天秤検査成績書」を選び、`sample/` フォルダの `denshitenbin_kensa_seisekisho01.jpg` を追加して判定します。

署名していないため、初回は OS の警告が出ます。

- Windows: SmartScreen の画面で「詳細情報」→「実行」を選びます。ウイルス対策ソフトが誤検知することもあります。
- macOS: 展開したフォルダに `xattr -dr com.apple.quarantine <フォルダ>` を実行してから起動します。Finder からダブルクリックすると、ターミナルも一緒に開きます。

環境ごとの注意点は次のとおりです。

- Tesseract は含まれません。Tesseract を使う様式（`configs/neomag.yaml` など）では、[OCR エンジン](#2-ocr-エンジン)の手順で別途インストールしてください。
- Linux で日本語が表示されないときは `sudo apt install fonts-noto-cjk` を実行してください。GUI にはデスクトップ環境が必要です（Raspberry Pi OS Lite では `document_OCR_cli` のみ使えます）。
- Raspberry Pi では OCR の処理に PC より時間がかかります。

更新するときは、新しいフォルダに展開してから、使っていた `configs/` と `settings.yaml` を移してください。

### リリース手順（開発者向け）

タグを push すると、[GitHub Actions](.github/workflows/build.yml) が各 OS 用にビルドして Releases に公開します。

```bash
git tag v0.1.0
git push origin v0.1.0
```

macOS 版は GPL のライブラリを含みます（[NOTICE](NOTICE)）。ビルド時に、対応するソース一式（`*-macos-sources.tar.gz`）も作ります。公開するにはリポジトリ変数 `PUBLISH_MACOS` を `true` にしてください。実行ファイルとソースが同じ Release に載ります。設定するまでは、ビルドとテストだけを行い、公開しません。Release から macOS 版のソースだけを消さないでください。

OpenCV を更新すると、`packaging/macos_sources.yaml` と wheel の dylib が一致しなくなり、CI が止まります。その場合は、新しい wheel の dylib ごとに版を調べ、一覧の版、URL、`sha256`、Homebrew のコミットを更新してください。確認は次のコマンドでできます。

```bash
uv run python packaging/build_macos_sources.py --output dist/sources.tar.gz --check-only
```

## セットアップ

ソースコードから実行する場合の手順です。

### 1. uv

Python 環境は [uv](https://docs.astral.sh/uv/) で管理しています。

```powershell
uv sync
```

`.venv` が作られ、必要なパッケージがすべて入ります（GUI 起動用の `OCR判定.bat` も初回に自動で実行します）。

### 2. OCR エンジン

2 種類から選べます。どちらもローカルで動きます。

| エンジン | 準備 |
| --- | --- |
| RapidOCR | `uv sync` で導入済み。PaddleOCR の PP-OCRv6 モデル（約 32MB）がパッケージに同梱されているため、実行時に通信しない |
| Tesseract | 本体を別途インストール: `winget install UB-Mannheim.TesseractOCR`。日本語の欄を読むにはインストール時に Japanese の言語データも追加する |

**日本語を含む書類は RapidOCR を推奨します**（電子天秤のサンプルでは RapidOCR は全項目を正しく読み、Tesseract は 12 項目が要確認になりました。詳しくは「[エンジンの比較](#エンジンの比較)」）。

どちらのエンジンも、ライセンスは商用利用が無償で可能なもの（Apache-2.0）です。

## GUI の使い方

`OCR判定.bat` をダブルクリックすると起動します（コマンドでは `uv run ocr_gui.py`）。

画面は 2 つのタブに分かれています。

| タブ | 使う場面 |
| --- | --- |
| 判定 | 毎日の作業。検査成績書の画像を読み取って合否を確認する |
| 様式設定 | 新しい種類の書類に対応させるとき、規格値を変えるとき |

### 判定タブ — 検査成績書を判定する

![判定タブ](docs/images/run_tab.png)

1. **様式**：書類の種類を選びます（`configs` フォルダの設定ファイルが一覧に出ます）。
2. **画像を追加…**：検査成績書のファイル（画像・PDF・Excel）を選びます。複数まとめて選べます。複数ページの PDF は、ページごとに 1 行として一覧に入ります。「一覧を空にする」でやり直せます。
3. **▶ 判定実行**：読み取りと判定を始めます。1 枚あたり RapidOCR で約 2 秒、Tesseract で数秒〜十数秒かかります。
4. **画像ファイルの一覧**：ファイルごとの総合判定が色付きで出ます（緑 = 合格、赤 = 不合格、橙 = 要目視確認、灰 = 読み取りエラー）。行をクリックすると、そのファイルの結果に切り替わります。
5. **総合判定**：選んだファイルの判定結果です。
6. **項目の一覧**：項目ごとの読取値・判定・理由です。NG は赤、要確認は橙の背景になります。「NG・要確認だけ表示」にチェックを入れると、問題のある項目だけに絞れます。
7. **画像**：読み取った位置が判定結果の色の枠で表示されます（汎用様式のみ）。一覧の行をクリックすると、その項目の枠が太く表示され、見える位置までスクロールします。

上の例では、2 枚目の画像で「総合判定」欄の「不合格」に○が付いているため、期待値（合格）と違うとして NG になっています。

**判定結果の見方**

| 総合判定 | 意味 | すること |
| --- | --- | --- |
| 合格 | すべての項目が規格内で、読み誤りの疑いもない | なし |
| 不合格 | 規格外の値（NG）がある | NG の項目を確認する |
| 要目視確認 | 読み誤りの疑いがある項目（要確認）が 1 つ以上ある | 「理由・メモ」を見て、原本と突き合わせる |
| 読み取りエラー | 選んだ様式と違う書類、または画像が不鮮明 | 様式の選択と画像を確認する |

マウスのホイールで画像を上下に、Shift + ホイールで左右にスクロールできます。Ctrl + ホイールで拡大・縮小します。

### 様式設定タブ — 画面の見方

既存の様式を「開く…」で開いた画面です。

![様式設定タブ](docs/images/editor.png)

1. **ファイル操作**：新規作成・開く・保存・名前を付けて保存。変更があるとファイル名の後ろに `*` が付きます。
2. **様式の基本設定**：様式名（判定タブの一覧に出る名前）、OCR エンジン、最小信頼度、説明。
3. **基準画像**：読み取り項目の枠が色付きで表示されます（青 = 文字、紫 = 数値、水色 = 表、橙 = マーク）。選んだ項目は太線になり、表は行・列の区切りが点線で表示されます。
4. **項目を追加**：「＋文字」「＋数値」「＋表」「＋マーク」を押してから、基準画像の上をドラッグして枠を描きます。右側のボタンで拡大・縮小、「全体」で画像全体を表示します。
5. **項目の一覧**：登録した項目と判定条件です。行をクリックすると、その枠に移動します。
6. **試し読み**：今の設定で実際に読んでみます。「基準画像」か、別の画像を選べます。
7. **選択中の項目**：選んだ項目の名前と判定条件を設定します。入力した内容はすぐに反映されます（数値の欄に数値以外を入れると文字が赤くなり、反映されません）。

### 新しい様式を作る

新しい種類の書類（例えば別のメーカーの検査成績書）を読めるようにする手順です。

**① 新規作成**

1. 「新規作成…」を押し、**記入済みの検査成績書の画像**を 1 枚選びます。これが「基準画像」になります。PDF（1 ページ目を使います）や Excel も選べます。
2. 様式名（例: `電子天秤検査成績書`）を入力します。
3. 保存先を聞かれるので、`configs` フォルダのまま保存します。基準画像も同じフォルダにコピーされます。

基準画像は、実際に読み取る書類と同じ様式で、なるべくまっすぐ・高解像度のものを選んでください。読み取る画像の傾き・位置ずれ・拡大縮小は、判定のときに自動で補正されます。

**② 読み取りたい欄を枠で囲む**

![表を追加したところ](docs/images/editor_new_table.png)

1. 項目の種類のボタン（例では「＋表」）を押します。
2. 基準画像の上で、読み取りたい欄をドラッグして囲みます。表は表全体（見出しを除いた値の部分）を囲むと、罫線から行数・列数が自動で設定されます。
3. 右下の欄で、項目名と判定条件を入力します。例では行の名前を「左前, 左後, 右後, 右前, 中心」、下限 `-2`、上限 `2`、小数桁数 `0` にしています。

枠を描いた後は、枠の中をドラッグで移動、角の白いつまみで大きさの変更、Delete キーで削除ができます。描くのをやめるときは Esc キーを押します。

**項目の種類と判定条件**

| 種類 | 使う欄の例 | 判定条件 |
| --- | --- | --- |
| 文字 | 機種名、OK/NG を書く欄 | 「期待する値」（例: `OK`）に一致すれば OK、「NG とする値」（例: `NG`）に一致すれば NG、どちらでもなければ要確認。両方空欄なら読み取って表示するだけ |
| 数値 | 計測値 1 つ | 下限・上限（ちょうど境界の値は合格）。「小数桁数」が違えば読み誤りとみなして要確認。「単位」（`g` など）を指定すると取り除いて読む。下限・上限とも空欄なら表示するだけ |
| 表 | 同じ条件の値が並んだ表 | 各セルを数値（または文字）として、同じ条件で判定する。斜線や矢印で値が無い欄は「読まないセル」に `行-列`（例: `5-3`）で指定して除外する |
| マーク | 手書きの○で選ぶ欄（合格/不合格、合/否 など） | 下で説明 |

- 文字欄と数値欄の「空欄でもよい」にチェックを入れると、何も書かれていなくても要確認になりません。
- 表のセルに `↑`・`〃`・`同上` と書かれていた場合は、上のセルと同じ値として判定します。
- 条件が違う列が混ざった表（例: 「荷重量」と「増・減」）は、列ごとに別の表として登録してください。

**③ 手書きの○で選ぶ欄（マーク）**

![マークの設定](docs/images/editor_mark.png)

1. 「＋マーク」を押し、1 つ目の選択肢（例: 「合格」の欄）を囲みます。選択肢の名前を聞かれるので入力します。
2. 続けて 2 つ目の選択肢（例: 「不合格」の欄）を囲み、名前を入力します。3 つ以上ある場合は続けて囲みます。終わったら Esc キーを押します。
3. 「期待する選択肢」で、合格のときに○が付くはずの選択肢を選びます。

○が期待と違う選択肢に付いていれば NG、どこにも付いていない・複数に付いている場合は要確認になります。○が欄からはみ出していても検出できるので、枠は欄に合わせて描いてください。

**④ 試し読みで確認する**

![試し読みの結果](docs/images/editor_testread.png)

1. 「試し読み（基準画像）」または「試し読み（画像を選ぶ）…」を押します。上の例は、「不合格」に○が付いた別の画像で試し読みしたところです。
2. 「試し読みの結果」に全項目の読取値と判定が出ます。行をクリックすると、該当の枠が赤で強調されます。
3. 項目の一覧にも、項目ごとの結果（表は OK・NG・要確認の件数）が出ます。

読み取りがおかしい項目があれば、枠の位置や大きさ、判定条件を直して、もう一度試し読みします。マークの判定が不安定な場合は、理由・メモ欄の「スコア」を見て、「マークの閾値」を調整してください（○がある選択肢のスコアより小さく、無い選択肢のスコアより大きい値にします）。

**⑤ 保存する**

「保存」を押すと設定ファイルに保存され、判定タブの「様式」の一覧に追加されます。

### NeoMag 様式の規格を変える

`configs/neomag.yaml` を開くと、枠ではなくフォームで設定します。表の位置は罫線から自動で検出されるため、枠の指定はありません。

![NeoMag 様式の設定](docs/images/editor_neomag.png)

- **計測表の各列**：小数桁数と規格。規格は「帳票の規格欄を読む」か「数値で指定」を選びます。
- **磁気特性値の規格**：下限・上限を入れた項目だけ判定します。空欄の項目は読み取って表示するだけです。

### 共通設定

メニューの「ファイル → 共通設定…」で、この PC で使う OCR エンジンの場所を設定します（`settings.yaml` に保存されます）。通常は空欄のままで動きます。

![共通設定](docs/images/settings.png)

## コマンドラインでの使い方

```powershell
uv run inspection_ocr.py sample/inspection_sample.gif                         # NeoMag 様式（既定）
uv run inspection_ocr.py sample/denshitenbin_kensa_seisekisho01.jpg --config configs/denshitenbin.yaml
uv run inspection_ocr.py scans/a.gif scans/b.gif --engine rapidocr            # 複数ファイル、エンジン指定
uv run inspection_ocr.py scans/a.gif --debug                                  # 読み取り位置を debug/ に画像出力
uv run inspection_ocr.py sample/denshitenbin_kensa_seisekisho01_digital.pdf --config configs/denshitenbin.yaml  # 電子 PDF
uv run inspection_ocr.py scans/batch.pdf --config configs/denshitenbin.yaml    # PDF はページごとに判定
```

> `python inspection_ocr.py ...` で実行するとシステムの Python が使われ、RapidOCR が見つかりません。`uv run` を使うか、先に `.venv\Scripts\Activate.ps1` で `.venv` を有効にしてください。

| オプション | 内容 |
| --- | --- |
| `--config パス` | 様式の設定ファイル（省略時は `configs/neomag.yaml`） |
| `--engine tesseract\|rapidocr` | OCR エンジン（省略時は設定ファイルの `engine`） |
| `--debug` | 読み取った位置を枠で描いた画像を `debug/` に保存 |

### 出力例（NeoMag 様式）

```text
ファイル : sample\inspection_sample.gif  (OCR: rapidocr)
ロットNo.: NN14092301

磁気特性値: Br=10.44  Hcb=9.92  Hcj=22.49  BHmax=26.05

     No.      長さ(mm)        幅(mm)      高さ(mm)         Gauss
    規格     19.9-20.1      9.9-10.1     1.95-2.05     1200-1400
----------------------------------------------------------------
       1         20.02         10.03          1.99          1310
       ...
     c/n          0/20          0/20          0/20          0/20
(NG=規格外, ?=要確認)

■ 総合判定: 合格
```

汎用様式では「項目 / 読取値 / 判定」の一覧を表示します。NG や要確認があると、「■ 指摘事項」に理由が一覧表示されます。

```text
■ 指摘事項
  [NG] 総合判定: 不合格 - 期待（合格）と違います; スコア 合格=0.00 不合格=2.41
  [要確認] 四隅 調整後 右後: =| - 数値として読めません ('=|')

■ 総合判定: 要目視確認
```

### 終了コード

| コード | 意味 |
| --- | --- |
| 0 | 合格 |
| 1 | 不合格（NG あり、要確認なし） |
| 2 | 要目視確認（要確認が 1 件でもある） |
| 3 | 読み取りエラー（表の構造を検出できない、基準画像と位置合わせできない、エンジンが見つからない） |

複数ファイル（または複数ページの PDF）を指定した場合は、最も悪い結果のコードを返します。

## 設定ファイル

通常は GUI で編集すれば十分です。GUI で保存すると、ファイル内のコメントは消えます。

### settings.yaml（PC 共通）

```yaml
tesseract_cmd: null        # null なら自動検出
tesseract_lang: jpn+eng    # 文字項目を Tesseract で読むときの言語
```

### configs/neomag.yaml（NeoMag 専用）

```yaml
type: neomag
name: NeoMag 検査成績書
engine: tesseract          # tesseract / rapidocr
min_confidence: 60         # これ未満の OCR 信頼度は要確認

columns:
  length: {decimals: 2, spec: from_document}
  width:  {decimals: 2, spec: from_document}
  height: {decimals: 2, spec: from_document}
  gauss:  {decimals: 0, spec: {min: 1200, max: 1400}}

magnetic: {}               # 例: Br: {min: 10.0, max: 11.0}
```

- `spec: from_document` は帳票の「検査規格」欄を読み取って使います。`{min: .., max: ..}` を書くとそちらが優先されます。
- **Gauss の規格は帳票に「N極中心」としか書かれていないため、初期値 1200〜1400 は仮の値です。実際の規格に設定してください。**
- 磁気特性値は規格を設定した項目だけ判定し、未設定の項目は読み取り結果の表示のみです。

## PDF・Excel の読み取り

画像と同じ様式（基準画像に枠を描いたもの）で、PDF と Excel も読めます。どれもページ画像にしてから位置合わせするので、様式の作り方は画像と同じです。

| 入力 | 読み方 |
| --- | --- |
| 画像（png / jpg / gif / bmp / tif） | OCR で読む |
| スキャン PDF | ページを画像にして（200dpi）、OCR で読む |
| 電子 PDF（文字を選択できる PDF） | ページを画像にして位置合わせし、枠の中の**文字をそのまま読む**（OCR しない） |
| Excel（xlsx / xlsm） | 開いたときに表示されるシートを、罫線とセルの値を描いた画像にし、枠の中の**セルの値をそのまま読む** |

- 電子 PDF と Excel でも、枠の中に文字が無い項目（手書きを貼り付けた欄など）は OCR で読みます。手書きの○（マーク）は、どの形式でもページ画像から判定します。
- 複数ページの PDF は、ページごとに 1 件の検査成績書として判定します。様式の基準に PDF を使うときは 1 ページ目を使います。
- スキャナーが OCR で埋め込んだ**透明な文字は使わず**、画像を OCR で読みます（スキャナーの OCR は読み誤りを含むため）。
- Excel の値は、セルの表示形式どおりに読みます（例: 表示形式 `0.00` の 1 は `1.00`、`+0;-0;0` の 4 は `+4`）。小数桁数の判定も表示どおりの値で行います。
- Excel の数式は、Excel で最後に保存したときの計算結果を読みます。計算結果が保存されていないファイル（プログラムで作ったファイルなど）では空欄になり、要確認になります。
- Excel の図形・画像・コメント（図形の○で囲んだ選択肢など）は読みません。選択肢は、セルに「合格」などの文字で書かれている場合に「文字」の項目として読めます。
- NeoMag 専用の様式も PDF を読めます（サンプルの GIF と同じ幅 500px で画像にして、罫線を検出します）。

サンプル（どちらも `configs/denshitenbin.yaml` で読めます）:

| ファイル | 内容 |
| --- | --- |
| `sample/denshitenbin_kensa_seisekisho01_digital.pdf` | 電子 PDF。電子天秤のサンプルの値の欄を、画像ではなく文字で書き込んだもの |
| `sample/denshitenbin_kensa_seisekisho01_scan.pdf` | スキャン PDF。電子天秤のサンプル画像を PDF にしたもの |

## 判定の仕組み

### NeoMag 専用

1. **表構造の検出** — 罫線を検出し、3 か所の二重罫線（「測定値」行の下 / No.20 の下 / c/n の下）を基準に各行・各列の位置を求めます。スキャン時の位置ずれには追従しますが、様式が変わると検出できません。
2. **OCR** — Tesseract はセルごとに、RapidOCR はページ全体を 1 回読んで各行をセルに割り当てます。
3. **良否判定** — 規格の範囲内なら OK、外れたら NG。
4. **読み誤りの検出** — 次の場合はその値を「要確認」にします。
   - 数字以外の文字が混じっている、小数桁数が設定と違う
   - OCR の信頼度が `min_confidence` 未満
   - RapidOCR で、1 行が隣のセルまでつながって読まれた
   - 読み取った 20 値から再計算した最大値・最小値・平均値が、帳票の値と合わない
   - 帳票の c/n と、判定した NG 件数が合わない

### 汎用様式

1. **位置合わせ** — 読み取る画像と基準画像の特徴点（ORB）を対応づけ、射影変換で基準画像の座標に合わせます。一致する点が少ない（別の様式の画像など）場合は読み取りエラーにします。電子 PDF・Excel の文字の位置も、同じ変換で基準画像の座標に合わせます。
2. **OCR** — 枠の位置で各項目を読みます（表は罫線に沿ってセルに分割）。電子 PDF・Excel で枠の中に文字があれば、OCR の代わりにその文字を使います。
3. **良否判定と読み誤りの検出** — 数値は書式（数字以外の文字、小数桁数）と信頼度、文字は期待値との一致で判定します。期待値と違う文字は「NG とする値」に一致しない限り NG ではなく要確認にし、読み誤りを NG と取り違えないようにしています。
4. **手書きマーク** — 罫線を除いた黒画素のうち、縦横とも文字 1 字分より大きい塊（○やチェックが文字とつながったもの）の面積をスコアにします。閾値（既定 0.3）以上の選択肢がちょうど 1 つならそれを選択とみなします。

要確認が 1 件でもあれば、総合判定は「要目視確認」になります。読み誤りを数字に当てはめて隠さないよう、OCR の文字種はあえて制限していません。

## エンジンの比較

商用利用が無償で可能なローカル OCR として RapidOCR（PP-OCRv6 small）と NDLOCR-Lite（国立国会図書館、CC BY 4.0）を Tesseract と比べ、RapidOCR を採用しました。

NeoMag サンプル画像と、それを人工的に劣化させた画像での計測値の正読数（全 80 値中）です。

| 画像 | Tesseract | RapidOCR | NDLOCR-Lite |
| --- | --- | --- | --- |
| 元画像 | 80 | 80 | 80 |
| ノイズ | 38 | 78 | 77 |
| JPEG 高圧縮 | 38 | 74 | 72 |
| ぼかし | 7 | 80 | 79 |
| 0.8 倍に縮小 | 11 | 80 | 80 |
| 0.3° 傾き | 44 | 80 | 80 |

電子天秤サンプル（汎用様式）での、目視で確認した 20 項目の正読数と、NG または要確認になった項目数（全 87 項目中。元の帳票はすべて OK）です。

| 画像 | Tesseract | RapidOCR | NDLOCR-Lite |
| --- | --- | --- | --- |
| 元画像 | 15（NG・要確認 12） | 20（0） | 13（26） |
| 回転・平行移動 | 17（11） | 20（0） | 14（25） |
| 0.7 倍に縮小 | 16（10） | 20（0） | 14（26） |
| 射影歪み | 17（10） | 20（0） | 15（24） |
| JPEG 高圧縮 | 17（11） | 20（0） | 15（24） |
| ノイズ | 12（21） | 20（0） | 15（22） |
| ぼかし | 16（17） | 19（2） | 15（25） |

- RapidOCR と Tesseract は、読み誤った値がすべて要確認になり、総合判定が「要目視確認」になりました（誤読を見逃して「合格」と出たケースはありませんでした）。
- NDLOCR-Lite は NeoMag 様式では RapidOCR と同等でしたが、電子天秤の様式では `-1` を `11`、`0` を `10` のように読み、規格外の NG として扱われました（ノイズを加えた画像では総合判定が「不合格」）。
- 処理時間は 1 枚あたり（Apple Silicon の Mac で計測）、RapidOCR が約 2 秒、Tesseract が約 4 秒、NDLOCR-Lite が約 3 秒でした。RapidOCR の上位モデル（PP-OCRv6 medium）は劣化画像でわずかに正読数が増えますが、約 10 秒かかるため採用していません。
- 劣化画像でも、位置合わせとマーク判定はどのエンジンでも正しく行えました。

## 注意事項

- **見逃しの可能性**: 形式が正しく規格内に収まる誤読（例: `1310` → `1330`）は、検出できないことがあります（NeoMag 様式では最大値・最小値・平均値との照合で一部を検出します）。重要な判定では、要目視確認になったものだけでなく、定期的に原本との突き合わせを行ってください。
- **手書きマーク**: ○・チェック・斜線のように文字より大きく書かれた印を検出します。文字の横に小さく書いたチェックなどは検出できないことがあります。新しい様式では、記入パターンの異なる画像で試し読みし、スコアを見て閾値を調整してください。
- 基準画像（`configs/` 内の画像）と `--debug` で出力した画像は検査成績書の内容を含みます。取り扱いに注意し、`debug/` は不要になったら削除してください。
